= Learn about NetApp Console agents
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
You enable NetApp Console capabilities by deploying Console agents, lightweight software components that provide a secure connection between your on-premises and cloud storage systems and the NetApp Console, enabling advanced storage orchestration and data services.

== What a Console agent does

A Console agent bridges the network gap between your storage systems and NetApp Console. It securely connects your infrastructure to the NetApp APIs and the Console, allowing you to:

* Discover and monitor storage systems across AWS, Azure, Google Cloud, and on-premises environments from the NetApp Console.
* Orchestrate storage provisioning and configuration tasks on storage systems from the NetApp Console. 
* Enable advanced data protection and optimization services.
* Associate your cloud provider credentials with a Console agent to securely track cloud service usage and connect deployments to the correct subscription for accurate billing and cost management.

=== Agent architecture

Agents operate with lightweight processes that:

* Pull or push data to and from the Console SaaS application (standard and restricted modes) or operate purely locally (private mode)
* Initiate all communication—the Console never initiates outbound calls to agents
* Connect to your storage systems using standard management protocols
* Use TLS 1.3 for secure communication with cloud providers and the NetApp Console APIs

=== Agent availability and operational requirements

Console agents are critical infrastructure for NetApp Console. NetApp Console can handle short outages, but agents must remain operational and reachable for uninterrupted management and data services. You are responsible for ensuring:

* Agents remain up and running
* Agents have network connectivity to required endpoints
* Infrastructure failures are resolved quickly
* Agent VMs are maintained and upgraded according to NetApp recommendations


== When you need a Console agent

You need to deploy at least one Console agent when you want to: 

* Use restricted or private deployment modes (Console installed in your own environment). Additional agents are required to enable some services.
* Access advanced data services (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification and more).
* Manage Cloud Volumes ONTAP systems.
* Perform advanced management tasks on on-premises ONTAP clusters.
* Track licenses, monitor storage health, and plan lifecycle upgrades.

Without an agent, you can perform basic storage discovery and access a limited set of monitoring and storage management features. However, most enterprise use cases require one or more operational agents.

link:concept-modes.html[Learn about NetApp Console deployment modes] to understand when you need an agent and the capabilities agents enable.


== Deployment options for Console agents

You can deploy Console agents in:

* Amazon Web Services (standard, restricted, or private modes)
* Microsoft Azure (standard, restricted, or private modes)
* Google Cloud (standard, restricted, or private modes)
* On your premises (standard or private modes)

Your Console deployment mode, storage environment, and data sovereignty needs determine where you deploy agents. Deploy multiple agents across environments for organizational separation or business needs.

After you deploy an agent, you register it with your NetApp Console organization to enable capabilities for that organization. You can associate multiple storage systems and data services with a single agent, or deploy multiple agents across environments for organizational separation or business needs.



=== Agents for the NetApp Console SaaS application (standard mode)
Deploy agents in your cloud or on-premises to bridge connectivity to the cloud-hosted Console SaaS application. Agents enable advanced features while the Console UI remains accessible from anywhere.

You can install agents directly from the Console when using the SaaS application (standard mode). You can install in AWS, Azure, or Google Cloud, or manually on your premises on your own Linux host or in your VCenter environment. 

When you install an agent on your premises, you can associate the respective cloud provider credentials to enable billing integration and data services.

=== Agents for NetApp Console in restricted mode

You need to install one agent from which users will access the NetApp Console. Additional agents are needed to enable data services and to manage storage systems. 

If you're using NetApp Console in restricted mode, you install agents from your cloud provider's marketplace, or by manually installing the software on your own Linux host in the cloud or on your premises or in your VCenter environment.

You'll need to install one agent from which users will access the NetApp Console. Additional agents are needed to enable data services and to manage storage systems. 

When you install an agent on your premises, you can associate the respective cloud provider credentials to enable billing integration and data services.

=== Agents for NetApp Console in private mode (on-premises or in the cloud with no outbound connectivity)

You need to install one agent from which users will access the NetApp Console. Additional agents are needed to enable data services and to manage storage systems. 

Install agents in your data center or air-gapped environment. Agents have no connectivity to NetApp API endpoints. All operations remain local, with full data sovereignty and control. 

You'll need to install one agent from which users will access the NetApp Console. Additional agents are needed to enable data services and to manage storage systems. 

When you install an agent on your premises, you can associate the respective cloud provider credentials to enable billing integration and data services.

=== Use multiple agents when needed

Each agent operates independently and can manage multiple storage systems and data services. Deploy multiple agents when you need:

* Isolation by storage type or organizational function
* Meet geographic or network segmentation requirements
