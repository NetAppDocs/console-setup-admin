= Deploy a Console agent in AWS from NetApp Console
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Deploy a Console agent in AWS without leaving the NetApp Console, so that you can start managing your AWS resources and data services.

Deploying a Console agent in AWS launches an EC2 instance running Linux and the Console agent software in a VPC of your choice.

.Before you begin

* link:concept-agent-install-options.html#agent-console-deploy[Learn when to deploy from the Console].
* Review link:reference-limitations.html[Console agent limitations].

[[aws-permissions-agent]]
== Step 2: Set up AWS permissions to deploy the Console agent

Give the Console only the AWS permissions it needs to deploy the Console agent in your VPC, based on the authentication method that you choose.

Choose one of these authentication methods and set up only what it requires:

.Authentication methods for deploying a Console agent
[cols="1a,2a,2a",options="header"]
|===
| Method
| What it does
| What you set up

| *Create role for me*
| The Console opens AWS CloudFormation Quick Create, which creates the deployment role that the Console assumes.
| Permissions for the AWS identity that submits the stack.

| *Assume role*
| The Console assumes an existing IAM role in your account.
| A policy and an IAM role.

| *AWS keys*
| The Console uses an AWS access key and secret key.
| A policy and an IAM user.
|===

With *Create role for me* and *Assume role*, the Console assumes an IAM role, called the *deployment role*, to deploy the Console agent. After deployment, the Console agent uses a separate IAM role attached to its EC2 instance, called the *agent role*. By default, the Console creates the agent role for you. link:#aws-agent-role[Learn how to use your own agent role].

[[aws-permissions-quick-create]]
=== Set up permissions for Create role for me (CloudFormation Quick Create)

Use an AWS identity that can create the CloudFormation stack and the deployment role, so that the stack completes without permission errors.

The identity that submits the CloudFormation Quick Create stack needs administrator permissions or the following minimum permissions. These permissions let CloudFormation create the deployment role. They are not the permissions of the agent role.

[[aws-permissions-assume-role-keys]]
=== Set up permissions for Assume role or AWS keys

If you choose *Assume role* or *AWS keys*, create a policy with only the permissions needed to deploy the Console agent, and attach it to the role or user that the Console uses.

If needed, you can restrict the IAM policy by using the IAM `Condition` element. https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html[AWS documentation: Condition element^]

.Steps

. Go to the AWS IAM console.

. Select *Policies > Create policy*.

. Select *JSON*.

. Copy and paste the following policy:
+
This policy contains only the permissions needed to launch the Console agent in AWS from the Console. link:reference-permissions-aws.html[View the permissions of the agent role].
+

----

        "iam:DeleteRole",
        "iam:PutRolePolicy",
        "iam:CreateInstanceProfile",
        "iam:DeleteRolePolicy",
        "iam:AddRoleToInstanceProfile",
        "iam:RemoveRoleFromInstanceProfile",
        "iam:DeleteInstanceProfile",
        "iam:PassRole",
        "iam:ListRoles",
        "ec2:DescribeInstanceStatus",
        "ec2:RunInstances",
        "ec2:ModifyInstanceAttribute",
        "ec2:CreateSecurityGroup",
        "ec2:DeleteSecurityGroup",
        "ec2:DescribeSecurityGroups",
        "ec2:RevokeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupIngress",
        "ec2:RevokeSecurityGroupIngress",
        "ec2:CreateNetworkInterface",

. Select *Next* and add tags, if needed.

. Select *Next* and enter a name and description.

. Select *Create policy*.

. Either attach the policy to an IAM role that the Console can assume or to an IAM user so that you can provide the Console with access keys:

* *Assume role*: Set up an IAM role that the Console can assume:
+
.. Go to the AWS IAM console in the target account.

.. Under Access Management, select *Roles > Create Role* and follow the steps to create the role.

.. Under *Trusted entity type*, select *AWS account*.

.. Select *Another AWS account* and enter the ID of the Console SaaS account: 952013314444

.. Select the policy that you created in the previous section.

.. After you create the role, copy the Role ARN so that you can paste it in the Console when you create the Console agent.

* *AWS keys*: Set up permissions for an IAM user so that you can provide the Console with access keys:
+
.. From the AWS IAM console, select *Users* and then select the user name.

.. Select *Add permissions > Attach existing policies directly*.

.. Select the policy that you created.

.. Select *Next* and then select *Add permissions*.

.. Ensure that you have the access key and secret key for the IAM user.

.Result

You now have a deployment role or an IAM user that has the required permissions. When you deploy the Console agent, you provide the role ARN or the access keys.

== Step 4: Deploy the Console agent

Provide your authentication, deployment, network, and security group details so that the Console launches the Console agent in your VPC.

.About this task

* Creating the Console agent from the Console deploys an EC2 instance in AWS using a default configuration. Do not switch to a smaller EC2 instance with fewer CPUs or less RAM after creating the Console agent. link:reference-agent-default-config.html[Learn about the default configuration for the Console agent].

* By default, the Console creates the agent role and its profile. If you provide your own agent role, ensure that you update it as new permissions are added in future releases. link:reference-permissions-aws.html[Learn more about the IAM policy for the Console agent].

.Before you begin

You should have the following:

* An AWS authentication method: *Create role for me*, *Assume role*, or *AWS keys*.

* A VPC and subnet that meets networking requirements.

* A key pair for the EC2 instance.

* Details about a proxy server, if a proxy is required for internet access from the Console agent.

* Completed link:#networking-aws-agent[Step 1].

* Completed link:#aws-permissions-agent[Step 2].

.Steps

. Select *Administration > Agents*.

. On the *Overview* page, select *Deploy agent > AWS*.

. In the *AWS credentials for agent deployment* section, choose one of the following authentication methods:
+
* *Create role for me*:
+
.. Select your AWS region and enter your AWS account ID. Optionally, enter an external ID.
.. Select *Open CloudFormation Quick Create*.
.. In AWS, acknowledge the terms and select *Create stack*.
.. When AWS finishes creating the role, return to the Console and confirm the role.

* *Assume role*: Enter the ARN of the IAM role and select *Validate credentials*.
* *AWS keys*: Enter the access key and secret key, and select *Validate credentials*.

. In the *Agent deployment details* section, provide details about the Console agent.
+
** Enter a name.
** Add custom tags (metadata).
** Choose whether you want the Console to create the agent role, or select an agent role that you link:#aws-agent-role[set up yourself].
** Choose whether you want to encrypt the Console agent's EBS disks. You have the option to use the default encryption key or to use a custom key.

. In the *Security group* section, choose whether to create a new security group or whether to select an existing security group that allows the required inbound and outbound rules.
