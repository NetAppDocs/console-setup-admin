= Learn about Console agent virtual machines
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
NetApp recommends deploying agents from the NetApp Console SaaS or from your cloud marketplace when possible. However, if you are using Restricted mode or Private mode, you may need to manually install the Console agent on a Linux VM. When you manually install the Console agent on a Linux VM, you are responsible for maintaining the underlying operating system and VM instance. You can install an agent in your VCenter environment using an OVA, or you can manually install the agent on a Linux VM in your cloud environment or on-premises. 

Each environment has different maintenance requirements and procedures. For example, if you deployed the Console agent using the OVA in VCenter, you perform maintenance through the VSphere client and a menu-driven maintenance console (`maint` user). This console lets you resize resources, configure network settings, and access diagnostics. If you deployed the Console agent by manually installing on a Linux VM (in AWS, Azure, Google Cloud, or on-premises), you perform maintenance using standard Linux tools and your cloud provider's management console. This includes applying OS security patches and connecting to the VM via SSH for diagnostics.


== Agents installed from NetApp Console
When you install an agent using the guided process in NetApp Console, most maintenance tasks are taken care of when the agent is upgraded automatically. For example, when the agent is upgraded, the underlying operating system is also updated, so you don't have to worry about applying OS security patches. You can also monitor the health of your agent and receive notifications about any issues in the Console Notifications Center.

This includes applying OS security patches and connecting to the VM via SSH for diagnostics.

| Scale CPU or RAM
