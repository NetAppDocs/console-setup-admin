= Secure NetApp Console
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Secure NetApp Console and ONTAP System Manager with deployment-mode controls, corporate identity controls, least-privilege roles, and read-only safeguards.

The following steps establish a security baseline for your organization. Follow the setup workflow for your deployment mode before you apply the controls in this topic. link:concept-modes.html[Learn about NetApp Console deployment modes].

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png[One] Choose a NetApp Console deployment mode and complete initial setup

[role="quick-margin-para"]
Create the organization and establish the first Organization admin. Complete the setup workflow that matches your deployment.

[role="quick-margin-list"]
* link:task-quick-start-standard-mode.html[Get started with NetApp Console in standard mode]
* link:task-quick-start-restricted-mode.html[Get started with NetApp Console in restricted mode]
* link:task-quick-start-private-mode.html[Get started with NetApp Console in private mode]

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png[Two] Organize the NetApp Console IAM hierarchy

[role="quick-margin-para"]
Match the organization hierarchy to your operational boundaries. Scope storage systems, data services, and Console agents to the projects that manage them.

[role="quick-margin-list"]
* link:task-iam-manage-folders-projects.html[Create folders and projects]
* link:task-iam-manage-resources.html[Associate resources with projects]

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png[Three] Add NetApp Console members and assign least-privilege roles

[role="quick-margin-para"]
Give each user, service account, and federated group only the access required for its responsibilities. Assign roles at the narrowest organization, folder, or project scope that supports the work.

[role="quick-margin-list"]
* link:task-iam-manage-members-permissions.html[Add members to your Console organization]
* link:concept-iam-rbac.html[Learn about role-based access control]
* link:reference-iam-predefined-roles.html[Review the predefined roles]
* link:task-iam-user-security.html[Manage member security]

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png[Four] Configure NetApp Console identity federation and federated groups

[role="quick-margin-para"]
Connect NetApp Console to your corporate identity provider (IdP) so users sign in with corporate credentials and your IdP can enforce its authentication policies. NetApp Console supports AD FS, Microsoft Entra ID, PingFederate, and generic SAML identity providers.

[role="quick-margin-para"]
Add federated users and groups to the Console organization and assign them Console roles. Federation does not replace Console membership or role assignments. link:task-iam-manage-members-permissions.html#add-members[Learn how to add a federated group].

[role="quick-margin-list"]
* link:task-federation-verify-domain.html[Verify your domain]
* link:task-federation-adfs.html[Federate with AD FS]
* link:task-federation-entra-id.html[Federate with Microsoft Entra ID]
* link:task-federation-ping.html[Federate with PingFederate]
* link:task-federation-saml.html[Federate with a SAML identity provider]

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png[Five] Enable read-only mode for a NetApp Console organization

[role="quick-margin-para"]
Require administrators to elevate their role before they make changes. This control reduces unintended changes to storage systems and data services.

link:task-enable-read-only-mode.html[Learn how to enable read-only mode].

NOTE: Read-only mode is not available when NetApp Console is in private mode.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png[Six] Enforce ONTAP permissions for ONTAP System Manager

[role="quick-margin-para"]
Enable *Force Credentials* on active Console agents that manage production ONTAP systems. Users then provide their ONTAP cluster credentials when they open ONTAP System Manager, and ONTAP applies their permissions.

link:task-ontap-access-agent.html[Learn how to enforce ONTAP permissions for ONTAP System Manager].

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-7.png[Seven] Secure NetApp Console automation with service accounts

[role="quick-margin-para"]
Keep automation separate from human accounts. Assign each service account the minimum role and scope it needs. Store its credentials securely and recreate them when they are lost or require rotation.

link:task-iam-manage-members-permissions.html#service-account[Learn how to add a service account].

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-8.png[Eight] Secure Console agent permissions, network access, and hosts

[role="quick-margin-para"]
Limit each agent's cloud permissions and network access. Protect web-console traffic, maintain the agent software, and apply AWS instance metadata safeguards where applicable.

[role="quick-margin-list"]
* link:reference-permissions.html[Review cloud provider permissions and network requirements]
* link:reference-networking-saas-console.html[Review network access requirements]
* link:task-installing-https-cert.html[Install a CA-signed certificate]
* link:task-configuring-proxy.html[Configure a proxy server]
* link:task-upgrade-agent.html[Upgrade the Console agent]
* link:task-require-imdsv2.html[Require IMDSv2 on EC2 instances]

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-9.png[Nine] Review NetApp Console audit activity and security controls

[role="quick-margin-para"]
Establish a recurring review process for members, group mappings, roles, credentials, agents, and recent operations. Remove access that is no longer required and investigate unexpected activity.

[role="quick-margin-list"]
* link:task-iam-audit-actions-timeline.html[Review the audit actions timeline]
* link:task-monitor-cm-operations.html[Monitor Console operations]

.Security baseline
* The first administrator used a corporate email address or an existing NSS account.
* The organization hierarchy matches operational boundaries.
* Members and federated groups have only the roles and scopes they need.
* Identity federation and corporate authentication policies protect federated sign-ins when required.
* Read-only mode protects the organization when the deployment mode supports it.
* *Force Credentials* protects access to production ONTAP systems.
* Automation uses service accounts with scoped roles instead of shared human credentials.
* Agent permissions, network access, certificates, proxy settings, and software versions meet your security requirements.
* Members, roles, credentials, agents, and recent operations receive recurring review.
